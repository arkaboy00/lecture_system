# Lecture Desktop

Ноутбучная часть [Lecture System](../README.ru.md). Что в ней:
- **`lecture_sync`:** забирает папки лекций с телефона ([`android/`](../android/README.ru.md)) по домашнему Wi-Fi;
- **`lecture_process`:** обрабатывает их (распознавание речи, материалы для конспекта, хранилище Obsidian);
- **`claude_skill/konspekt`:** скилл Claude Code, который пишет конспекты.

В фоне ничего не работает: процесс живёт, пока открыто окно. Служба синхронизации на телефоне сама останавливается, когда программа сообщает «всё получено».

Автор: [arkaboy00](https://github.com/arkaboy00)

## Как пользоваться

1. На телефоне: Lecture Capture → «Синхр.» → «Начать синхронизацию».
2. На ноутбуке: значок «Лекции» на рабочем столе → «Синхронизировать», затем «Обработать». В первый раз нужно ввести 6-значный код с экрана телефона.
3. В Claude Code: `/konspekt` (см. «Конспекты» ниже).

Лекции попадают в `~/Documents/Lectures/<папка>`. Папку можно поменять полем `inbox` в `%APPDATA%\LectureDesktop\config.json`. Завершённой считается только лекция с `ended` в `lecture.json`; идущая лекция забирается в том виде, в каком она есть сейчас.

Консольный режим (для тестов и отладки):

```
python -m lecture_sync --cli [--code 123456] [--inbox ПАПКА] [--config ФАЙЛ]
```

## Установка (из этой папки)

```
py -3.14 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
powershell -File install_shortcut.ps1
powershell -File install_skill.ps1
```

- **Ярлык «Лекции»** запускает `LectureSync.pyw` через `pythonw` из `.venv`.
- **Скрипт скилла** копирует `claude_skill\konspekt` в `~/.claude/skills/konspekt`. Его нужно запускать заново после каждой правки скилла.
- **Синхронизации** нужна только стандартная библиотека Python.

## Обработка

```
.venv\Scripts\python -m lecture_process [process|transcribe|status [--json]|index] [папка ...] [--all]
```

**Что делает `process`** (по умолчанию; кнопка «Обработать» делает то же):
1. `transcribe` — распознавание речи;
2. подбор слайдов из сборника курса;
3. сборка материалов для конспекта.

Без указания папок обрабатываются все завершённые лекции. Результат пишется в `~/Documents/Lectures_work/<папка>/` (поле `work` в конфиге). В саму папку лекции ничего не записывается.

**`transcript.json`** — результат для программ, все времена в секундах от `lecture_start` на одной шкале (как времена телефона переводятся на неё, объяснено в `lecture_process/lecture.py`):
- названия, тип лекции, номер части;
- аудиосегменты;
- фото: тип и флаги «неактуально» и «перерисовать»;
- заметки и отметки;
- распознанные куски с временем каждого слова.

**`notes_input/`** — то, что читает Claude Code, пересобирается при каждом запуске:
- **`transcript.md`:** речь абзацами с временем по часам;
  - метки `[ФОТО n · время · доска]` в моменты съёмки;
  - заметки `[ЗАМЕТКА]` и отметки `[ОТМЕЧЕНО КНОПКОЙ]` с телефона;
  - перерывы в записи;
- **`photos/`:** только актуальные фото, повёрнутые правильно, длинная сторона не больше 2000 пикселей (формулы на доске остаются читаемыми);
- **`info.json`:** названия, тип, часть, дата, список фото с типом и флагом «перерисовать»;
- **`slides.md`:** подобранные слайды курса, если они нашлись.

**Распознавание.** faster-whisper `large-v3` на видеокарте:
- **скорость на RTX 5070 Laptop:** модель грузится около 4 с, два часа звука распознаются примерно за 15 минут;
- **первый запуск** скачивает около 3 ГБ в кэш Hugging Face;
- **детектора речи (VAD) нет:** Silero выбрасывал настоящую тихую речь, поэтому распознаётся весь звук. Затем `asr.clean` убирает то, что Whisper выдумывает на тишине: титры, эхо подсказки, зацикливания;
- **сомнительные куски** остаются с пометкой «(?)»;
- **сырой результат модели** кэшируется по каждому аудиофайлу в `<work>/<папка>/asr/`, поэтому смена фильтров и повторный запуск после синхронизации проходят мгновенно.

## Термины лекции и материалы курса

**Подсказки распознаванию (hotwords)** подаются в каждое 30-секундное окно Whisper. Начальная подсказка (prompt) доходит только до первого окна, поэтому её недостаточно. Порядок подсказок:
1. **`<work>/<папка>/terms.txt`:** термины этой лекции в порядке записи (сначала тетрадь), до ~300 знаков. Их выписывает скилл konspekt с фото.
2. **Глоссарий предмета `glossary/<Предмет>.txt`:** до 600 знаков в сумме с терминами лекции.

Изменение подсказок запускает повторное распознавание при следующем `process`: они входят в ключ кэша.

**Результат на лекции 15.10.2026** (материаловедение, 2 ч):
- распознанного текста стало больше: 85 тысяч знаков вместо 54;
- сомнительных кусков меньше: 51 вместо 86;
- сортировка терминов «редкие первыми» ухудшила результат.

**PDF курса** в `<хранилище>/<предмет>/Материалы/` (`lecture_process/slides.py`) обрабатываются без модели:
1. **индекс** строится один раз: текст страниц и оглавление, кэш в `<work>/_sources/`;
2. **подбор разделов** к лекции идёт по характерным словам речи в 20-минутных окнах и по `terms.txt`;
3. **текст найденных разделов** попадает в `notes_input/slides.md` со ссылками `[[файл.pdf#page=N]]`.

## Конспекты (Claude Code)

Конспекты пишет Claude Code по скиллу `claude_skill/konspekt/SKILL.md`. В Claude Code: `/konspekt` или «конспект по последней лекции» / «по всем новым».

**Что делает скилл:**
1. Один раз читает все фото и пишет `terms.txt`.
2. Запускает второй проход распознавания.
3. Читает `notes_input/`.
4. Пишет конспект `<хранилище>/<предмет>/<дата> <название>.md`:
   - краткое содержание;
   - разделы;
   - неясные места;
   - свёрнутый полный текст;
   - фото и слайды в сворачиваемых блоках.
5. Дописывает, что повторить к контролям, в `<предмет>/Контроль/`: `РК-1.md`, `РК-2.md`, `Экзамен.md`, `Разобрать.md`.

Хранилище: `~/Documents/Конспекты` (поле `vault` в конфиге). В Obsidian эту папку нужно открыть как хранилище.

**Устройство хранилища** (`lecture_process/vault.py`):
- **Генерируемые страницы:**
  - `Главная.md`: предметы, последние конспекты, лекции без конспекта;
  - `<предмет>/<предмет>.md`: конспекты предмета, файлы «Контроль», материалы курса.
- **Как обновляются:** их собирает из заголовков (front matter) конспектов команда `python -m lecture_process index`. Она запускается после «Обработать» и после каждого конспекта. Править эти страницы вручную нельзя.
- **Настройки Obsidian** (`.obsidian/app.json`: вложения рядом с заметкой, ссылки следуют за переименованием) записываются один раз, если их нет.

**Статус конспектов: `python -m lecture_process status`.** Показывает обработанные лекции и их конспекты.
- В заголовке конспекта хранятся `источник` (папка лекции) и `версия_входа` (`input_version` материалов). Поэтому лекция, изменённая более поздней синхронизацией, показывается как «конспект устарел».
- Существующий конспект не перезаписывается: скилл пишет рядом копию «(обновлено …)».

## Протокол синхронизации

Задаётся телефоном (`android/core/.../sync/SyncProtocol.kt`):
- **поиск телефона:** UDP на порту 47811;
- **обмен:** HTTP на порту 47812, запросы `/hello`, `/pair`, `/manifest`, `/file` (с Range), `/ack`, `/done`;
- **скачивание:** файл пишется в `<файл>.part`, оборванная загрузка докачивается через `Range`, после проверки SHA-256 файл переименовывается;
- **сетевые ошибки:** повторы около минуты с повторным поиском телефона, так что переподключение телефона к Wi-Fi не обрывает синхронизацию.

## Тесты

```
.venv\Scripts\python -m unittest discover -s tests
```

- **`test_process.py`:**
  - шкала времени: mono против часов, перезагрузки, поздние правки, оборванные строки;
  - события этапа 8: тип и флаг фото, заметки, отметки, части;
  - фильтры очистки;
  - статус конспектов и страницы хранилища.
- **`test_slides.py`:** индекс PDF и подбор разделов на сгенерированном PDF, порядок и бюджет подсказок.
- **`test_client.py`** (с поддельным телефоном на стандартном HTTP-сервере):
  - сопряжение и потеря сопряжения;
  - докачка после обрыва связи;
  - пропуск неизменённых файлов, выросшие файлы;
  - папка, переименованная на телефоне;
  - телефон, пропавший во время повторов;
  - отмена.
