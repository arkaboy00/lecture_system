# Lecture Capture (Android)

Приложение для телефона из [Lecture System](../README.ru.md). Записывает «черновик лекции»:
- звук сегментами;
- фото доски, тетради и слайдов;
- текстовые заметки и отметки «важно»;
- журнал событий, который только дописывается.

Обработка (распознавание речи, конспекты в Obsidian) идёт на ноутбуке ([`desktop/`](../desktop/README.ru.md)). Единственный договор между частями — формат папки лекции, описанный в [docs/SPEC.md](../docs/SPEC.md).

Автор: [arkaboy00](https://github.com/arkaboy00)

## Что где лежит

- `core/` — чистый Kotlin без Android:
  - модель событий и JSON-кодек;
  - журнал `EventLog`, который только дописывается (fsync на каждую строку);
  - воспроизведение `events.jsonl` в `LectureState`, `lecture.json`, имена папок, `LectureStore`;
  - сервер синхронизации.

  Модульные тесты идут на JVM.
- `app/` — интерфейс на Compose. `LectureSession` — единственное место в процессе, которое пишет в открытую лекцию.
- `tools/` — скрипты для компьютера:
  - `phone.py` — помощник adb: установка, выдача разрешений, нажатие по testTag, копирование папок лекций с телефона;
  - `check_lecture.py` — проверка скопированной папки лекции (формат журнала, seq, ссылки на файлы, ffprobe);
  - `stage0_check.py` — приёмочный сценарий этапа 0 на подключённом телефоне;
  - `stage1_check.py` — сценарии звука: `segments`, `forcestop`, `kill [fg|bg]`, `long [мин]`, `manual [с]`;
  - `stage2_check.py` … `stage8_check.py` — приёмочные сценарии следующих этапов.

**Проверка восстановления после убийства процесса.** В отладочной сборке есть `DebugKillReceiver` (`app/src/debug`). Команда `adb shell am broadcast -n com.arka.lecturecapture/.DebugKillReceiver` убивает приложение так же, как это делает система. Обычные способы не подходят: `run-as kill` не видит процессы приложения, а `am kill` не трогает процесс с foreground-сервисом.

## Сборка и тесты

Gradle работает на JDK из Android Studio (команды из этой папки):

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat :core:test :app:assembleDebug
python tools\phone.py install
python tools\phone.py grant
python tools\stage0_check.py
```

Релизная сборка подписана отладочным ключом: приложение личное. На телефон оно ставится по локальной сети: `python -m http.server 8765 --directory dist`.

У каждого интерактивного элемента есть `testTag`, он виден как `resource-id` в `uiautomator dump`. Всплывающим меню и диалогам нужен свой `Modifier.exposeTestTags()`, потому что это отдельные окна.

## Состояние

- **Этап 0 (каркас):** готов, проверен на Poco M3 (Android 12, MIUI 13).
- **Этап 1 (звук):** готов. Запись Ogg/Opus в foreground-сервисе, восстановление после сбоя, перезапуск сервиса системой проверены на Poco M3 (`SPEC.md` §12). Заглушение звонком не проверено: в Poco нет SIM.
- **Этап 2 (главный экран):** готов.
  - сетка фото (галочка = актуально) и крупный просмотр;
  - отмена в снэкбаре;
  - полоса сегментов;
  - переименование, удаление незавершённой лекции.

  Проверка: `tools/stage2_check.py grid|delete`.
- **Этап 3 (фото):** готов. Съёмка CameraX в `.pending`, каталог пачки, сохранение, устойчивое к сбоям (`SPEC.md` §12a). Проверка: `tools/stage3_check.py batch|cancel|crash`.
- **Этап 4:** готов. Зум, экспозиция и фокус камеры, уборка остатков после сбоя, экран настроек батареи. Проверка: `tools/stage4_check.py camera|recover|battery`.
- **Этап 6 (синхронизация):** готов. Служба синхронизации по Wi-Fi на телефоне запускается по кнопке, клиент на ноутбуке лежит в `desktop/` (`SPEC.md` §12d).
- **Этап 7 (архив):** готов.
  - все лекции с сортировкой, группировкой и фильтром;
  - правки завершённых лекций;
  - удаление с двойным подтверждением и меткой синхронизации;
  - «открыть папку в…».

  Проверка: `tools/stage7_check.py list|edit|folder|delete|resume`.
- **Этап 8 (разметка):** готов.
  - тип кадра «слайд» и цветные рамки;
  - тип и флаг «перерисовать» у отдельного фото;
  - заметки и звезда «важный момент»;
  - следующая часть лекции.

  Результаты в `SPEC.md` §12f, проверка: `tools/stage8_check.py markup|archive|part`.
- **Дальше:** этап 5, ручная приёмка на Samsung S10e (чек-лист в `SPEC.md` §9). План после него — в [docs/ROADMAP.md](../docs/ROADMAP.md).
