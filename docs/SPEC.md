# Lecture Capture — Android-приложение для съёмки конспекта лекций

Это ТЗ собрано из обсуждения архитектуры. Всё, что помечено **[ПРОВЕРИТЬ]**, — предположение, которое нужно проверить на реальном телефоне или в документации до того, как на нём что-то строить.

## 1. Цель и место в системе

Система состоит из двух частей:

1. **Телефон (этот репозиторий).** Во время лекции создаёт «черновик лекции»: аудиозаписи, фото доски и тетради, временные метки, пометки. Никакой обработки, только надёжный захват.
2. **Ноутбук (отдельно, не в этом репо).** Дома папка с телефона копируется на компьютер (Syncthing или вручную). Скрипты распознают речь (faster-whisper, локально), нарезают транскрипт по меткам фото, а затем модель собирает конспект в vault Obsidian.

Связь между частями — **только формат папки лекции** (раздел 4). Приложение не должно знать ничего про обработку.

Контекст по предметам: сопромат, термех, кратные интегралы и ряды, материаловедение. Лектор обычно проговаривает всё вслух, доска дублирует это формулами и схемами, поэтому **аудио первично, фото дополнительны**. Фото нужны для точных формул, обозначений и схем.

## 2. Среда и ограничения

- **Целевое устройство:** Samsung Galaxy S10e (оболочка One UI), Android 12 **[ПРОВЕРИТЬ в настройках телефона]**. Сейчас оно к компьютеру не подключается.
- **Тестовое устройство на время разработки: Poco M3** (оболочка MIUI), подключено по adb. Версию Android узнать командой `adb shell getprop ro.build.version.release` **[ПРОВЕРИТЬ]**: Poco M3 выходил с Android 10 и мог обновиться до 11 или 12. Всё, что завязано на версию системы, писать с учётом разных API.
- Kotlin, Jetpack Compose, CameraX. minSdk 29, targetSdk 34 (выбор можно обсудить).
- Приложение для личного использования, ставится вручную (не из Google Play).
- Разработчик уже писал под Android на Kotlin.
- **Доступ к общему хранилищу зависит от версии Android:** на Android 10 нужны `WRITE_EXTERNAL_STORAGE` и `requestLegacyExternalStorage`, на 11 и новее доступ ко всем файлам (`MANAGE_EXTERNAL_STORAGE`) или выбор папки через системный диалог. Реализовать так, чтобы работало на обоих телефонах.
- **Тестирование выполняет Claude Code сам** (так уже делалось в прошлом проекте): сборка Gradle, установка по adb, выдача разрешений (`pm grant`, `appops set` для доступа ко всем файлам), запуск приложения, нажатия и ввод (`input tap`, `input keyevent`), чтение экрана (`uiautomator dump`), чтение логов (`logcat`), принудительная остановка (`am force-stop`), копирование файлов с телефона (`adb pull`) и проверка их на компьютере (разбор `events.jsonl`, `ffprobe` для аудио, если он установлен). Чтобы интерфейсом было удобно управлять автоматически, у всех кнопок и элементов списка должны быть `contentDescription` или `testTag`.
- **Порядок работы:** сначала предложи план этапа и жди подтверждения, а потом пиши код. Не переходи к следующему этапу без явного «ок».

## 3. Принципы

1. **Сырые данные не правятся.** Журнал событий только дополняется. «Удаление» старого фото это пометка в журнале, а сам файл не трогается. Физически удаляет скрипт на ноутбуке.
2. **Единственное исключение:** кадры, которые пользователь сам не выбрал в каталоге съёмки, удаляются сразу (он их уже просмотрел).
3. **Всё пишется на диск сразу.** Нет состояния, которое существует только в памяти и пропадёт при вылете. Отдельных «резервных сохранений» нет: каждое событие и каждый файл сохраняются в момент появления.
4. **Журнал, а не база.** Состояние экрана строится воспроизведением `events.jsonl`. Тот же код используется при восстановлении после вылета.
5. **Минимализм интерфейса.** Крупные кнопки, ничего лишнего, защита от случайных нажатий.

## 4. Формат данных

Папка лекции в общем хранилище (не в приватном каталоге приложения, иначе Syncthing не прочитает):

```
/storage/emulated/0/Lectures/2026-10-06_1015_Сопромат_Лекция-5/
  lecture.json
  events.jsonl
  audio/001.ogg
  audio/002.ogg
  photos/101203_1.jpg
  photos/101416_1.jpg
  .pending/            # кадры текущей, ещё не разобранной пачки
```

Имя папки: `ГГГГ-ММ-ДД_ЧЧММ_<предмет>_<название>`, из имён убираются недопустимые символы файловой системы (`\ / : * ? " < > |`), пробелы и `_` внутри частей заменяются на `-`. Кириллица допустима. Если папка с таким именем уже есть, добавляется `_2`, `_3`, …

Во время лекции папка не переименовывается (в ней открыты файлы записи). Если название поменяли, папка переименовывается при `lecture_end`.

В корне `Lectures/` лежит `.nomedia`, чтобы фото лекций не попадали в галерею.

### lecture.json

Текущие названия и флаги лекции, удобно читать без разбора журнала:

```json
{
    "v": 1,
    "subject": "Сопромат",
    "title": "Лекция 5",
    "kind": "lecture",
    "created": "2026-10-06T10:15:02+03:00",
    "ended": "2026-10-06T11:45:10+03:00",
    "device": "M2010J19CG",
    "app": "0.1"
}
```

- `kind`: `lecture` | `seminar`, выбирается переключателем в диалоге «Сохранить и выйти».
- `ended`: появляется вместе с `lecture_end`; папка готова к обработке.

В отличие от журнала этот файл перезаписывается, но всегда атомарно (временный файл → `fsync` → переименование), поэтому после вылета в нём либо старая, либо новая версия. Источник истины всё равно `events.jsonl`: если `lecture.json` нет или он испорчен, приложение собирает его заново из журнала.

### events.jsonl

Одна JSON-строка на событие, файл только дописывается. После каждой записи делать `flush` и `fd.sync()`.

Общие поля каждого события (идут первыми в этом порядке):
- `e`: тип события;
- `seq`: номер события в файле, 1, 2, 3, …;
- `ts`: ISO-8601 с часовым поясом (`2026-10-06T10:15:02+03:00`);
- `mono`: `SystemClock.elapsedRealtime()` в миллисекундах. Нужно, чтобы смещение внутри аудио не зависело от перевода часов телефона;
- `boot`: `Settings.Global.BOOT_COUNT` в момент события (нет, если система его не отдаёт). Два значения `mono` можно сравнивать, только если у них одинаковый `boot`.

**Порядок строк ≠ хронология.** Событие `photo` пишется при «Сохранить», но с временем спуска, поэтому может стоять после более поздних событий. Хронологию строить по (`boot` в порядке появления, `mono`), между разными `boot` по `ts`.

**Оборванная строка.** Если телефон выключился посреди записи строки, последняя строка может быть неполной. Читатель её пропускает, файл не правится; приложение перед следующей записью дописывает `\n`, и дальше сразу идёт событие `recovered`.

Незнакомые поля читатель игнорирует (совместимость с будущими версиями).

**Правки после `lecture_end`** (экран «Лекции», этапы 7–8): в завершённую лекцию могут дописываться только `meta` (предмет, название, `kind`), `obsolete`, `restored`, `retype`, `redraw`, `note_removed` и `unmark`; `lecture.json` перезаписывается, папка переименовывается под новые названия. Для читателя это не ошибка. Итоговый `kind` — из последнего `meta` с `kind`, иначе из `lecture_end`. Любое другое событие после `lecture_end` — несогласованность.

События:

```
{"e":"lecture_start","seq":1,"ts":"...","mono":...,"boot":123,"v":1,"subject":"Сопромат","title":"Лекция 5","device":"...","app":"0.1"}
                                                                   // part: 2, 3… у следующих частей лекции (нет поля = 1)
{"e":"meta","title":"Лекция 6", ...}                              // смена названия посреди лекции; поля subject/title/kind необязательны
{"e":"audio_start","file":"audio/001.ogg", ...}
{"e":"audio_stop","file":"audio/001.ogg","reason":"user", ...}     // user | error | recovered; dur_ms — длительность по файлу, если известна
                                                                   // recovered: время события = audio_start + dur_ms (реальный конец звука), boot как у audio_start
{"e":"audio_silenced","file":"audio/001.ogg", ...}                 // система заглушила микрофон (например, звонок)
{"e":"audio_unsilenced","file":"audio/001.ogg", ...}
{"e":"photo","file":"photos/101203_1.jpg","type":"board","batch":3, ...}   // type: board | notebook | slide
{"e":"obsolete","file":"photos/101203_1.jpg", ...}
{"e":"restored","file":"photos/101203_1.jpg", ...}
{"e":"retype","file":"photos/101203_1.jpg","type":"slide", ...}    // смена типа сохранённого фото, действует последнее
{"e":"redraw","file":"photos/101203_1.jpg","on":true, ...}         // флаг «перерисовать рисунки», действует последнее
{"e":"note","text":"...", ...}                                     // заметка; время = момент открытия поля ввода
{"e":"note_removed","note":17, ...}                                // заметка с seq 17 удалена
{"e":"mark", ...}                                                  // кнопка «важный момент» (звезда)
{"e":"unmark","mark":21, ...}                                      // отметка с seq 21 снята
{"e":"recovered","note":"...", ...}
{"e":"lecture_end","kind":"lecture", ...}
```

### .pending

Кадры текущей пачки ещё не попали в журнал, поэтому время спуска хранится в имени файла: `.pending/<boot>_<mono>_<epoch_ms>.jpg` (`x` вместо `boot`, если он неизвестен). Пока CameraX пишет кадр, файл называется `….jpg.part`; такие недописанные файлы игнорируются. При «Сохранить» для каждого кадра сначала пишется событие `photo` (с временем спуска), потом файл переносится в `photos/ЧЧММСС_n.jpg`; если приложение упало между этими шагами, при открытии лекции перенос доделывается (кадр находится по `boot` + `mono`).

**Привязка фото к аудио (делает ноутбук):** смещение в файле = `photo.mono − audio_start.mono` для сегмента, внутри которого лежит фото. Если между событиями был перезапуск телефона (`boot_count` изменился, есть событие `recovered`), использовать `ts`. Точности в одну-две секунды достаточно, гнаться за миллисекундами не нужно.

**Время фото** это момент нажатия спуска, а не момент нажатия «Сохранить» (иначе привязка к речи поедет).

## 5. Аудио

- Запись идёт в **foreground-сервисе** (`foregroundServiceType="microphone"`, постоянное уведомление), а не в Activity. Она должна продолжаться при сворачивании и закрытии приложения, при открытии камеры, при блокировке экрана.
- Старт записи только по нажатию кнопки на видимом экране (на Android 12 запуск foreground-сервиса из фона ограничен).
- Формат: **Ogg/Opus** через `MediaRecorder` (`OutputFormat.OGG` + `AudioEncoder.OPUS`, API 29+), моно, 16 кГц, около 32 кбит/с (параметры для речи, подобрать на тесте) **[ПРОВЕРИТЬ: поддержка на S10e и поведение при обрыве записи]**.
  - Запасной вариант: WAV 16 кГц моно через `AudioRecord` (самый надёжный при вылете: длину в заголовке можно восстановить по размеру файла).
  - Критерий выбора: после принудительного закрытия приложения файл должен открываться (хотя бы без последних секунд).
- Каждый запуск записи создаёт **новый сегмент** (`001.ogg`, `002.ogg`, …). Пауза (например, у лектора звонок) это остановка и новый старт. В списке между сегментами виден обрыв и его длительность.
- Заглушение микрофона системой (звонок, другое приложение): отслеживать через `AudioManager.registerAudioRecordingCallback` и `isClientSilenced` **[ПРОВЕРИТЬ]**, писать `audio_silenced` / `audio_unsilenced` и показывать в списке.
- Остановка записи кнопкой требует **подтверждения**: обычный диалог «Вы уверены?», кнопка подтверждения в нём стоит в другом месте экрана, чем кнопка, открывшая диалог. Так случайное двойное нажатие в одну точку ничего не завершит. Это общее правило для всех подтверждений.
- Оболочки производителей усыпляют и убивают фоновые приложения (Xiaomi MIUI на Poco M3 делает это особенно агрессивно, Samsung One UI тоже). В приложении нужна подсказка и проверка настроек: для Samsung добавить в «Никогда не засыпающие» в настройках батареи, для MIUI включить «Автозапуск» и режим батареи «Нет ограничений». Партиальный wake lock на время записи.
- Различия оболочек влияют на надёжность фоновой записи, поэтому результаты, полученные на Poco M3, нельзя автоматически считать верными для S10e (см. этап 5).

## 6. Фото

Отдельный полноэкранный режим камеры (CameraX), максимальное качество JPEG: на фото читается почерк.

Поток:
1. Кнопка «Фото» открывает камеру. Можно сделать **несколько кадров**. Время каждого кадра фиксируется в момент нажатия спуска. Кадры сразу пишутся в `.pending/`.
2. Кнопка «Продолжить» открывает **каталог только что снятых кадров**:
   - последний кадр отмечен галочкой по умолчанию;
   - тап по кадру открывает его на весь экран с зумом (оценить резкость), галочка ставится отдельно;
   - внизу переключатель **«доска / тетрадь»** (по умолчанию значение прошлой пачки) и кнопка «Сохранить».
3. «Сохранить»: отмеченные кадры переносятся в `photos/`, в журнал пишутся события `photo` (с исходным временем съёмки и общим `batch`), неотмеченные удаляются. Возврат на главный экран.
4. Тип один на всю пачку. Если снимал и доску, и тетрадь, это две пачки.
5. «Отмена» (с подтверждением) удаляет всю пачку.
6. Автофокус по тапу, вспышка по умолчанию выключена, поворот экрана не блокировать (доску часто удобнее снимать горизонтально).

## 7. Интерфейс

Пока только портретная ориентация (камера решит про поворот отдельно, этап 3).

**Стартовый экран:**
- незавершённые лекции с кнопкой «Продолжить» (при продолжении пишется `recovered`);
- у незавершённой лекции есть кнопка «Удалить» (этап 2): на случай, если лекцию начали случайно. Подтверждение диалогом с содержимым (минуты аудио, число фото) и предупреждением, что это необратимо; кнопка подтверждения не в том же месте, что «Удалить» на карточке. Папка стирается с телефона целиком: единственное, кроме неотмеченных кадров, место, где приложение удаляет данные, потому что решение принимает пользователь;
- кнопка «Начать» закреплена внизу экрана, чтобы длинный список незавершённых не уводил её за край;
- «Новая лекция»: предмет (поле + кнопки-подсказки из прошлых лекций и стандартного списка: Сопромат, Термех, Кратные интегралы и ряды, Материаловедение), название подставляется само («Лекция N+1» по прошлым лекциям этого предмета), кнопка «Начать».
- Одновременно открыта только одна лекция.

**Главный экран (как в обычных приложениях):**
- вверху шапка: предмет и название лекции, кнопки настроек и меню; под шапкой состояние записи и таймер текущего сегмента;
- основное поле: сетка фото (время и тип на миниатюре); в углу каждого кружок-галочка, как выбор в Telegram: **галочка стоит = фото актуально**, сняли галочку = фото неактуально (серое, событие `obsolete`), поставили обратно = `restored`; файл не удаляется; snackbar «Отменить» ~10 с; тап по фото открывает его на весь экран с зумом и той же галочкой;
- под шапкой сворачиваемая полоса аудио: «Аудио: N сегм., M мин · паузы: K», по тапу список сегментов (время, длительность, заглушения, обрывы) и пауз;
- внизу две крупные кнопки: **аудио** (запуск, затем стоп с подтверждением) и **фото**.

**Меню:**
- название предмета и лекции (изменение → событие `meta`);
- «Сохранить и выйти»: диалог с переключателем **лекция / семинар**, подтверждение, остановка записи, событие `lecture_end`;
- позже: настройки.

Лекция завершается именно через «Сохранить и выйти», а кнопка аудио завершает только текущий сегмент.

**Экран «Лекции» (этап 7):** кнопка в шапке стартового экрана.
- Список всех папок лекций: карточка с датой, лекция/семинар, длительность аудио, число фото, метки «не завершена» и синхронизации («✓ на ноутбуке», «не на ноутбуке», «изменена после синхр.»).
- Сортировка «сначала новые / сначала старые»; переключатель «По предметам» (разделы, сворачиваются); чипы «Все / предмет» — фильтр. Выбор запоминается.
- Кнопка папки в углу (и на экране лекции): путь к папке (можно скопировать) и «Открыть в…» — системный выбор приложения (системные «Файлы», сторонние файловые менеджеры, Samsung «Мои файлы»).
- Экран лекции: сетка фото с полноэкранным просмотром, список аудиосегментов (время, длительность, паузы; прослушивание — на ноутбуке), переключатель лекция/семинар. У завершённой лекции можно менять галочки фото, предмет и название (папка переименовывается); незавершённую можно только смотреть или «Продолжить запись».
- «Удалить лекцию» (меню): два подтверждения — «Удалить?» с содержимым и состоянием синхронизации, затем «Точно удалить?», где кнопки поменяны местами (двойной тап попадает в «Отмена»).

## 8. Устойчивость и восстановление

- При запуске приложение сканирует папку `Lectures` и ищет лекции без `lecture_end`. Если находит, предлагает **продолжить**.
- Проверка последнего аудиосегмента: если файл не закрыт корректно, записать `audio_stop` с `reason: "recovered"` и проверить, что файл открывается.
- Если в `.pending/` остались кадры, предложить доразобрать пачку.
- В событие `recovered` писать `boot_count` (`Settings.Global.BOOT_COUNT`), чтобы ноутбук знал, можно ли доверять `mono`.

## 9. Этапы

Каждый этап заканчивается автоматической проверкой на Poco M3 (способ описан в разделе 2). То, что автоматизировать нельзя (например, реальный звонок или живая речь), помечено «вручную» и проверяется пользователем.

**Этап 0. Каркас.** Проект, разрешения (микрофон, камера, уведомления, доступ к общему хранилищу или выбор папки), создание папки лекции и `events.jsonl`, класс записи журнала (append + sync) и воспроизведение журнала в состояние. Модульные тесты на формат и воспроизведение.

**Этап 1. Аудио (самое рискованное, делать первым).** Foreground-сервис, запись сегментов, события, диагностика заглушения. Приёмочные проверки на Poco M3:
- запись 10 минут со смахиванием приложения из недавних (автоматически: `input swipe`/keyevent, затем `adb pull` и проверка длительности файла);
- блокировка экрана во время записи (автоматически);
- открытие стандартной камеры во время записи, например через `am start -a android.media.action.IMAGE_CAPTURE` (автоматически);
- принудительная остановка приложения (`am force-stop`): файл должен открываться, в журнале нет битых строк (автоматически);
- сегменты после паузы получают правильные `audio_start` / `audio_stop` (автоматически);
- проверка, что в файле не только тишина: пользователь говорит рядом с телефоном и проверяет вручную (автоматически можно проверить только валидность файла, а не содержимое речи);
- входящий звонок: должен появиться `audio_silenced` в журнале (**вручную**, звонок на тестовый телефон с другого).
По результатам принять решение по формату (Opus или запасной) и записать, какие проверки реально прошли.

**Этап 2. Главный экран.** Список, подтверждение остановки, меню с названием лекции, пометка «неактуально».

**Этап 3. Фото.** Камера, `.pending/`, каталог, выбор типа, сохранение.

**Этап 4. Восстановление и доводка.** Раздел 8, подсказка про батарею (Samsung и MIUI), мелкие улучшения. Автоматическая проверка восстановления: остановить приложение посреди записи и посреди пачки фото, запустить заново, убедиться, что лекция предлагается к продолжению и данные целы.

**Этап 5. Приёмка на основном телефоне (S10e).** Когда приложение стабильно на Poco M3, пользователь ставит его на S10e и вручную проходит короткий чек-лист: настройки батареи One UI, запись 20 минут с заблокированным экраном и закрытым приложением, звонок (заглушение: `audio_silenced` / `audio_unsilenced`, на Poco не проверено), фото и каталог, восстановление после принудительной остановки, проверка, что папка попадает на ноутбук. Все расхождения с Poco M3 (формат аудио, поведение сервиса, доступ к хранилищу) фиксируются в этом файле.

**Этап 6. Синхронизация телефон → ноутбук (своя, без Syncthing).** Решено 2026-10-15 вместо Syncthing: ничего не ставить дополнительно и ничего не держать в фоне. Делается после первых реальных лекций (их пока забираем `adb pull` / кабелем).
- Только домашний Wi-Fi пользователя (есть доступ к роутеру); в университете не синхронизируем.
- Телефон: кнопка «Синхронизировать» запускает foreground-сервис (`dataSync`, уведомление с прогрессом и кнопкой «Остановить»). Приложение можно закрыть и выгрузить — сервис работает дальше. Сервис сам завершается, когда ноутбук сообщил «всё получено», или после нескольких минут без запросов; кнопка принудительной остановки — в приложении и в уведомлении.
- Внутри сервиса маленький HTTP-сервер в локальной сети; ноутбук находит телефон широковещательным UDP-запросом.
- Сопряжение один раз: телефон показывает 6-значный код, ноутбук его вводит, дальше запросы подписываются общим ключом.
- Только телефон → ноутбук. Ноутбук получает список файлов (путь, размер, SHA-256), скачивает недостающее (`events.jsonl` докачивается с места остановки, оборванные загрузки — через Range), проверяет SHA-256. Незавершённые лекции тоже можно забирать, но обрабатывать — только с `ended`.
- Обрыв связи не ломает ни телефон, ни ноутбук: ноутбук повторяет, в худшем случае часть файлов скачивается заново.
- Телефон помнит, какие лекции ноутбук подтвердил полностью: значок «на ноутбуке ✓», и только такие лекции потом можно удалять с телефона для освобождения места.
- Ноутбук: маленькая программа (Python, значок на рабочем столе) с кнопкой «Синхронизировать», отдельный репозиторий; позже к ней подключается обработка (распознавание, конспект).

**Этап 7. Экран «Лекции».** Просмотр и правка всех лекций на телефоне, сортировка, группировка и фильтр по предметам, удаление с двойным подтверждением и меткой синхронизации, переход к папке в файловом менеджере (раздел 7). Воспроизведение аудио в приложении решено не делать (2026-10-15).

**Этап 8. Разметка (пункты 1, 2, 3, 5, 9, 10, 11 из `IDEAS.md`).** Тип кадра «слайд» и цветные рамки (доска зелёная, слайд синий, тетрадь оранжевая); смена типа и флаг «перерисовать» (красные уголки) у отдельного кадра в каталоге и у сохранённого фото, в том числе в завершённой лекции; текстовые заметки (время — момент открытия поля, черновик переживает вылет); кнопка-звезда «важный момент» с отменой; «следующая часть» лекции (новая папка «… ч.2», `part` в `lecture_start`). Ноутбук вставляет заметки и отметки в `transcript.md`, скилл конспекта их использует.

## 10. Вне рамок этого репозитория (для понимания контракта)

- Скрипт на ноутбуке читает `events.jsonl`, распознаёт аудио и считает абсолютное время реплик как «начало сегмента + смещение».
- Скрипт чистки удаляет файлы, помеченные `obsolete` (и не снятые `restored`).
- Сборка конспекта в Obsidian, глоссарии предметов и промпты тоже на ноутбуке.

Приложение должно только гарантировать корректность папки лекции.

## 11. Решённые вопросы (2026-10-14)

- Подтверждение остановки: диалог, кнопка подтверждения не в том же месте, что кнопка вызова (разделы 5, 7).
- Лекция / семинар: поле `kind`, переключатель в диалоге «Сохранить и выйти» (разделы 4, 7).
- Хранилище: «доступ ко всем файлам» (`MANAGE_EXTERNAL_STORAGE`) на Android 11+, `requestLegacyExternalStorage` на Android 10. Обычные файлы проще и надёжнее выбора папки через системный диалог (атомарный перенос, `fsync`, прямая запись `MediaRecorder` и CameraX).
- Названия и флаги: отдельный `lecture.json`, журнал остаётся только дописываемым (раздел 4).
- Тестовый телефон: Poco M3 (M2010J19CG), Android 12 / SDK 31, MIUI 13. `pm grant` и `appops set` по adb на нём работают.

## 12. Результаты этапа 1 на Poco M3 (2026-10-14)

Формат: **Ogg/Opus через `MediaRecorder`** (моно, 16 кГц на входе, 32 кбит/с, ~5 КБ/с ≈ 18 МБ/час). Запасной WAV не нужен.

Проверено автоматически (`tools/stage1_check.py`):
- `segments`: два сегмента с паузой, `audio_start` / `audio_stop` корректны, длительность файла совпадает с журналом с точностью до ~1 с (файл чуть короче: `audio_start` пишется до запуска микрофона).
- `forcestop`: после `am force-stop` через 39 с записи файл открывается целиком (38,9 с). При «Продолжить» сегмент закрывается `audio_stop` с `reason: "recovered"`, `dur_ms` из файла и временем конца звука.
- `kill fg` и `kill bg`: процесс убит SIGKILL (как это делает система; в отладочной сборке через `DebugKillReceiver`). Система перезапускает сервис (`START_STICKY`) примерно через 1 с, `startForeground` проходит, микрофон **не заглушён** даже когда приложение в фоне. Запись продолжается новым сегментом, теряется ~2,5 с, пишется `recovered`.
- `long 10`: 10 минут одним сегментом (618,6 с): смахивание из недавних (процесс MIUI не убила), 3 минуты с выключенным экраном, стандартная камера открыта 2,5 минуты. Во время записи пользователь снимал видео встроенной камерой: наша запись **не заглушилась** (в файле нет тишины), `audio_silenced` не появился.
- В файлах настоящий звук (пики −4…−9 дБ), а не тишина.

Не проверено:
- Входящий звонок и `audio_silenced` / `audio_unsilenced`: на Poco нет SIM-карты. Проверить на S10e (этап 5) или звонком в мессенджере по Wi-Fi.
- Живая речь на расстоянии лектора: проверится на первой реальной лекции.

## 12a. Результаты этапа 3 на Poco M3 (2026-10-14)
